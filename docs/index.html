SlintPlot: native charts for Slint in Rust

SlintPlot draws charts with Slint's own Path, Rectangle and Text elements. They are not images: charts stay sharp at any scale, follow the theme and dark mode, and react to the mouse.

Cartesian charts

Line, bar, horizontal bar, scatter and bubble charts; stacked, mixed, stepped and filled variants.

Radial charts

Pie, doughnut, polar area and radar charts.

Time and heatmaps

Time series with date axes, matrix heatmaps and GitHub-style calendar heatmaps.

Hierarchies and business

Treemaps, sunbursts, funnels, waterfalls, dumbbells and gauges.

Interactive

Tooltips, hover highlights, clickable legends, click callbacks, zoom and pan, keyboard navigation.

Large datasets

Min-max decimation and on-demand data reading for millions of points.

Getting started

1. Add the dependencies

SlintPlot is used both as a regular dependency (the register! macro) and as a build dependency (to find its .slint files).

[dependencies]
slint = "1.18"
slintplot = "0.1"

[build-dependencies]
slint-build = "1.18"
slintplot = "0.1"

2. Make the library importable: build.rs

fn main() {
    let config = slint_build::CompilerConfiguration::new().with_library_paths(
        std::collections::HashMap::from([("slintplot".into(), slintplot::library_path())]),
    );
    slint_build::compile_with_config("ui/app.slint", config).unwrap();
}

3. Use a chart: ui/app.slint

import { ChartEngine, ChartLegendPosition, ChartSeriesType, LineChart } from "@slintplot";
export { ChartEngine } // required, so Rust can connect it

export component App inherits Window {
    preferred-width: 800px;
    preferred-height: 500px;

    // Every property is listed here, most at its default value. Properties at
    // their default value can be dropped: `LineChart { labels: ...; datasets: ...; }`
    // is a complete chart.
    LineChart {
        // Data
        labels: ["Jan", "Feb", "Mar", "Apr", "May", "Jun"];
        datasets: [
            {
                label: "2025",
                values: [12, 19, 8, 15, 22, 18],
                points: [],                         // scatter and time series charts only
                color: transparent,                 // transparent: the theme's next color
                hidden: false,
                fill: true,                         // default false
                tension: 0.4,                       // default 0: straight lines
                stepped: false,
                series-type: ChartSeriesType.auto,  // or .line / .bar in mixed charts
            },
            { label: "2026", values: [15, 22, 13, 24, 26, 30], tension: 0.4 },
        ];
        title: "Revenue";                           // default ""

        // Look
        show-legend: true;
        legend-position: ChartLegendPosition.top;
        show-tooltip: true;
        show-points: true;
        show-values: false;
        animated: true;

        // Value axis
        begin-at-zero: false;
        stacked: false;
        stacked-percent: false;
        fixed-range: false;
        min-value: 0;
        max-value: 100;
        logarithmic: false;
        x-title: "";
        y-title: "";
        value-prefix: "";
        value-suffix: "";
        value-decimals: -1;                         // -1: automatic

        // Large datasets, zoom and pan
        decimate: true;
        zoom-enabled: false;
        view-start: 0;
        view-end: 1;
        min-view: 0.0005;

        // Callbacks
        category-clicked(index) => { debug("clicked category", index); }
        legend-toggled(index) => { debug("toggled dataset", index); }
    }
}

Import only the charts you use, plus ChartEngine, which must always be imported and exported. Charts you don't import cost nothing: Slint generates code only for the components your UI uses. register! connects the whole engine either way.

4. Connect the engine: src/main.rs

slint::include_modules!();

fn main() -> Result<(), slint::PlatformError> {
    let app = App::new()?;
    slintplot::register!(app);
    app.run()
}
Software renderer: to draw lines, areas and pies with Slint's software renderer, enable Slint's software-renderer-path feature: slint = { version = "1.18", features = ["software-renderer-path"] }.

How it works

Charts are Slint components. Geometry such as line paths, bar positions and axis ticks is computed in Rust by the ChartEngine global's pure callbacks, which slintplot::register! connects. Because the callbacks are pure, Slint recomputes them automatically when the chart's size, data or theme changes.

  • Data is a Slint model. Set it in .slint or from Rust; changing a row updates the chart.
  • Colors are optional. Datasets and slices without a color take the next color of the active theme.
  • Two requirements: export ChartEngine from your root .slint file, and call slintplot::register! once after creating the component.

Mixed charts

Any dataset in a line or bar chart can be drawn as the other type with series-type. Lines in a bar chart go through the bar centers, and stacking keeps lines and bars apart.

This example sets only the properties for this feature; the chart sections above list all of them.

BarChart {

        { label: "Average", values: [10, 14, 12, 13], series-type: ChartSeriesType.line },

100% stacked bars

With stacked-percent: true, each category of a BarChart or HorizontalBarChart is split into the datasets' shares, so every bar fills the axis from 0% to 100%. Labels and tooltips show the percentages. This is the classic chart for survey answers. The percentage labels use largest remainder rounding, so each bar's labels add up to exactly 100%.

Answers with a natural order, from "Every day" to "Never", read best in shades of one color, as in the screenshot and the example below: a fade from dark blue to light blue. Give each dataset its own color, which always wins over the theme; without one, the datasets take the theme's colors.

This example sets only the properties for this feature; the chart sections above list all of them.

TimeSeriesChart

Lines over a time axis. Datasets use points, whose x is the number of seconds after time-origin. The axis picks round times for its ticks: seconds, minutes, hours, days, months or years, depending on the visible range, and the tooltip shows the date and time. Hovering anywhere above or below the lines shows the values at that time. Tick steps follow the visible span, from years down to seconds. When no tick falls on a midnight (or on a January), the first tick also shows the date (or the year), so a zoomed-in axis always says when it is. Zoomed in between points, lines continue to the edges of the plot.

    show-points: false;

CalendarHeatmap

A year (or any span) of daily values, like GitHub's contribution graph: one column per week, one row per weekday, with month and weekday labels and a "Less … More" legend. TreemapChart

One rectangle per item, with an area proportional to its value, laid out with the squarified algorithm so the rectangles stay close to square. Items with the same group are placed together under the group's label and share the group's color; the legend lists the groups, and clicking one hides it. Without groups, every item gets its own theme color and there is no legend. Missing, zero and negative values take no space. Labels and values are written in the rectangles where they fit, in white or dark text depending on the fill.

import { ChartLegendPosition, TreemapChart } from "@slintplot";

    title: "World population (millions)";
    items: [
        { label: "India", value: 1464, group: "Asia" },
        { label: "China", value: 1416, group: "Asia" },
        { label: "Nigeria", value: 237, group: "Africa" },
        { label: "United States", value: 347, group: "Americas" },
        { label: "Brazil", value: 212, group: "Americas", color: transparent },  // transparent: the group's color

A hierarchy drawn as rings: the top level innermost, and each item's angle its share of its parent. Top-level items take the theme's colors in order and their children a lighter shade of their parent's. Axes and formatting

Cartesian charts and HorizontalBarChart share these axis options:

  • Titles: x-title below the x axis, y-title above the y axis.
  • Fixed range: fixed-range: true with min-value and max-value, so the axis stays put when the data changes.
  • Logarithmic axis: logarithmic: true, with ticks at 1, 2 and 5 times powers of ten. Values that aren't positive are left out.
  • Formatting: value-prefix, value-suffix and value-decimals (-1 for automatic) apply to the value axis, tooltips and data labels. Pies and radar charts have them too. A minus sign goes before the prefix: "-$5". Separators and dates follow ChartTheme.language (see Languages).

This example sets only the properties for this feature; the chart sections above list all of them.

LineChart {
    labels: ["Q1", "Q2", "Q3", "Q4"];
    datasets: [{ label: "Users", values: [12, 340, 2900, 61000] }];
    logarithmic: true;
    y-title: "Users (log scale)";
    value-suffix: " users";
}

A second value axis

Datasets with right-axis: true are plotted against a second value axis on the right, for two measures of different size or unit in one chart. The axis appears when a dataset uses it, and has its own settings: y2-title, y2-value-prefix, y2-value-suffix, y2-value-decimals, y2-fixed-range with y2-min-value and y2-max-value, y2-logarithmic and y2-begin-at-zero. Tooltips and data labels write each value in its own axis' format, and stacked datasets stack on their own axis.

The right axis gets as many ticks as the left one, at steps such as 15 or 40, so its ticks sit on the left axis' grid lines. When either axis is fixed or logarithmic they can't line up; then the right axis chooses its own ticks, without grid lines. It works in LineChart, BarChart, ScatterChart, BubbleChart and TimeSeriesChart; other charts ignore right-axis.

BarChart {
    labels: ["Jan", "Feb", "Mar", "Apr"];
    datasets: [
        { label: "Temperature", values: [-1.5, -1.2, 1.2, 5.5], series-type: ChartSeriesType.line },
        { label: "Rainfall", values: [86, 136, 88, 103], right-axis: true },
    ];
    y-title: "Temperature";
    value-suffix: " °C";
    y2-title: "Rainfall";
    y2-value-suffix: " mm";
}

Two value axes are easy to misread: the heights of the two datasets can't be compared, and where they cross means nothing. Give both axes a title, and make it clear which dataset belongs to which, for example with a line for one and bars for the other.

let language = match sys_locale::get_locale().unwrap_or_default().get(..2) {
    Some("de") => ChartLanguage::German,
    Some("nb" | "nn" | "no") => ChartLanguage::Norwegian,
    Some("sv") => ChartLanguage::Swedish,
    _ => ChartLanguage::English,
};
app.global::<ChartTheme>().set_language(language);

Japanese and Chinese need a font with their characters. Desktop systems have one; in the browser, Slint only has its built-in Inter font, so the web gallery leaves these two languages out.

Interaction

  • Tooltips and highlights. Line, bar and radar charts show every dataset's value for the category under the mouse. Scatter and bubble charts show the nearest point, pies the slice under the mouse, and treemaps and sunbursts the item under the mouse with its share of the total. Funnels add each stage's share of the first and previous stage, waterfalls the running total, dumbbells the change between two datasets, and gauges the band under the mouse.
  • Legend. Clicking an entry toggles the dataset's or slice's hidden flag; the axes rescale to the visible data. In a treemap, it hides or shows a group, and in a sunburst a top-level item.
  • Clicks. category-clicked, point-clicked, slice-clicked, item-clicked, stage-clicked and step-clicked report what was clicked. Clicking a sunburst item with children zooms into it, and clicking the center zooms out.
  • Keyboard. Every chart can be used without a mouse. Click a chart (or tab to it) and a focus ring appears; the arrow keys then move the highlight and tooltip, Home and End jump to the ends, and Enter clicks. Charts report their title as an accessibility label.

Updating data from Rust

Datasets and slices are ordinary Slint models. Use a VecModel and change rows; the chart updates on its own.

use std::rc::Rc;
use slint::{Model, ModelRc, VecModel};

slint::include_modules!();

fn main() -> Result<(), slint::PlatformError> {
    let app = App::new()?;
    slintplot::register!(app);

    let values = Rc::new(VecModel::from(vec![3.0, 7.0, 4.0]));
    let datasets = Rc::new(VecModel::from(vec![ChartDataset {
        label: "Sales".into(),
        values: values.clone().into(),
        tension: 0.4,
        ..Default::default()
    }]));
    app.set_datasets(datasets.clone().into());

    // Later: append a value, or replace a row.
    values.push(9.0);
    if let Some(mut ds) = datasets.row_data(0) {
        ds.fill = true;
        datasets.set_row_data(0, ds);
    }
    app.run()
}

Here App declares in-out property <[ChartDataset]> datasets; and passes it to a chart with datasets <=> root.datasets;. The generated Rust types (ChartDataset, ChartXY, ChartSlice, ...) come from slint::include_modules!().

Streaming

For live data, give a dataset a model that appends new values and drops the oldest. Charts read their models on demand and follow the model's change notifications, so an update costs one frame, not a copy of the data. VecModel works for small windows, but remove(0) moves every remaining value. For large windows, use a ring buffer, like the StreamModel in the example apps (stream_model.rs, about 70 lines):

/// The latest `capacity` values of a stream.
pub struct StreamModel<T> {
    values: RefCell<VecDeque<T>>,
    capacity: usize,
    notify: ModelNotify,
}

impl<T: Clone + 'static> StreamModel<T> {
    /// Appends values, dropping the oldest ones beyond the capacity.
    pub fn extend(&self, new: impl IntoIterator<Item = T>) {
        let mut values = self.values.borrow_mut();
        let before = values.len();
        values.extend(new);
        let added = values.len() - before;
        let dropped = values.len().saturating_sub(self.capacity);
        values.drain(..dropped);
        let len = values.len();
        drop(values);
        if added == 0 {
            return;
        }
        if dropped >= before {
            self.notify.reset();
        } else {
            self.notify.row_removed(0, dropped);
            self.notify.row_added(len - added, added);
        }
    }
}

impl<T: Clone + 'static> Model for StreamModel<T> {
    type Data = T;
    fn row_count(&self) -> usize { self.values.borrow().len() }
    fn row_data(&self, row: usize) -> Option<T> { self.values.borrow().get(row).cloned() }
    fn model_tracker(&self) -> &dyn ModelTracker { &self.notify }
}

// A time series dataset of the latest 10,000 points:
let points = Rc::new(StreamModel::new(10_000, Vec::new()));
datasets.push(ChartDataset { points: points.clone().into(), ..Default::default() });
// Later, from a timer:
points.extend(new_points);
  • Batch the samples. Data can arrive far faster than a screen refreshes. Collect the samples that arrived since the last frame and add them with one extend per frame, from a slint::Timer of about 16 ms; the stress app streams 100,000 samples a second this way.
  • Keep time series in time order. TimeSeriesChart finds the visible points with a binary search, so each dataset's points must be sorted by x. Appending newer points keeps them sorted. Scatter and bubble charts take points in any order.
  • Let the x axis move. In line and bar charts, stream the labels along with the values (another StreamModel), so the categories move with the data. Time series axes follow the points' times on their own.
  • Mind the window size. How many values a chart can show and still update at 60 frames per second depends on the chart and the machine; see streaming limits.

The gallery's Live data sample streams a time series at 10 to 60 updates a second, and the stress app streams up to 8 datasets at up to 100,000 samples a second, with windows from 1,000 values to everything it has received.

Large datasets

  • Turn off point markers with show-points: false. Each marker is an element.
  • Keep decimation on (decimate: true, the default). A line with more than twice as many points as pixels is drawn as one span per pixel column, which looks the same and draws far faster: about 250 ms instead of 24 s for 3 lines of 1,000,000 points in the software renderer.
  • Zoom in. Values are read from the models on demand, so a zoomed-in chart reads only the visible values, and changes outside the view cause no work.

Performance

SlintPlot draws every chart with Slint's own elements: a path per line, a rectangle per bar, a text per label. That keeps charts sharp, themeable and interactive, but every element costs drawing time, and that cost grows with the data. The stress test app, slintplot-stress, was built to find where it starts to matter: it pushes each chart type from 100 to 1,000,000 points, streams new data at 60 Hz, and shows the layout and frame times live. Use it to check what's fast enough for your app before you build it; we use it to catch slowdowns in SlintPlot before a release.

How it's measured

The numbers below come from slintplot-stress --bench, which renders each configuration without a window:

  • Machine: Apple M4 (10 cores, 16 GB), macOS 27, a release build of SlintPlot 0.1.2 with Slint 1.18.
  • Renderer: Slint's software renderer, on one CPU core, into a 1280×800 pixel buffer.
  • Data: three datasets (three groups for the sunburst), random walks.
  • Frame: the chart's layout plus drawing every pixel, measured once per configuration. Showing it on a screen isn't included. Hover is the next frame after the mouse moves over the chart.
  • Runs: each number is the median of three runs. The runs differed by at most ±8%, most by ±1–3%.

At 60 frames per second, a frame has 16.7 ms. Frames below that can be animated and streamed smoothly; slower ones are fine for charts that change now and then.

Streaming limits

How much data can a chart show while it streams, and still update at 60 or 30 frames per second? slintplot-stress --bench-stream measures it: each update appends one value to each of three datasets, drops the oldest, and renders a full frame. It grows the window (the values kept per dataset) in 1-2-5 steps from 1,000 to 10,000,000, and times each size: the 95th percentile of up to 100 updates, the median of three runs.   • Zoomed in, the data size doesn't matter. A view of the latest 1,000 values updates in about 7 ms with 1,000 values kept per dataset or with 10,000,000: the chart finds the visible values with a binary search and reads only those.
  • Showing everything, decimation sets the limit. A decimated line updates at 60 fps with 50,000 values per dataset, and takes 130–150 ms with 500,000. Below about 2,500 values (twice the plot width in pixels) lines aren't decimated, so up to there all line charts cost the same.
  • Scatter charts read every point, since their points can be in any order, so even zoomed in they slow down from about 20,000 points per dataset.
  • One value per update. At higher data rates, the samples that arrive between frames are added in one batch per frame (see Streaming). The benchmark doesn't measure those larger batches; the stress app shows their effect live, at up to 100,000 samples a second.

What the numbers mean

  • Up to about 1,000 points per dataset, every chart fits in a 60 fps frame, except the sunburst (26 ms).
  • Lines of any size stay usable with decimation, which is on by default: 6 ms at 10,000 points, 26 ms at 100,000 and about 250 ms at 1,000,000 for a full redraw. Hovering stays at about 4 ms at every size, and zooming in to 0.1% of a million points brings a frame to 46 ms. Without decimation, a million-point line takes 24 s to draw.
  • Bars, scatter markers and the one-shape-per-item charts grow with the count. For animation and streaming, keep them to about 1,000 bars, markers or items; at 10,000 a frame takes 26–307 ms.
  • Up to 10,000 points, drawing takes most of the time. Computing the chart takes 1–6 ms (19 ms for a line with point markers) of frames of 6–307 ms. With decimated million-point lines it's the other way round: reading and decimating the data takes 192 ms of the 244 ms frame.

What isn't measured

  • GPU renderers. Desktop apps use Slint's FemtoVG or Skia renderer by default, which draw on the graphics card. They haven't been benchmarked; expect different, usually faster, drawing.
  • The browser. The web gallery runs SlintPlot as WebAssembly; it isn't benchmarked, and is likely slower.
  • Other machines. Everything above is from one fast computer. Older or low-power hardware is slower; embedded devices are untested.
  • Memory use and start-up time.

Limitations

What SlintPlot 0.2 doesn't do yet, or does with restrictions:

  • Rust only. The chart geometry is computed in Rust and connected with register!, so the library can't be used from Slint's C++, JavaScript or Python APIs. For the same reason, charts aren't drawn in Slint's live preview or SlintPad.
  • Platforms. Tested on desktop (macOS, Windows and Linux) and in the browser with WebAssembly, from version 0.1.2: the gallery runs in the browser. Embedded (MCU) builds are untested. With Slint's software renderer, enable its software-renderer-path feature, or charts aren't drawn.
  • 14 built-in languages. ChartTheme.language covers 14 languages; for others, set the ChartLocale fields yourself. Grouping is always in thousands (no Indian lakh grouping, and four-digit numbers are grouped in every language), digits are Western, and right-to-left layout isn't supported.
  • Time zones. Time axes are in UTC, with an optional fixed offset. Named time zones and daylight saving time changes aren't supported.
  • Two value axes at most, and only in line, bar, scatter, bubble and time series charts: horizontal bar charts have one value axis.
  • Zoom, pan and decimation work in the cartesian charts only (line, bar, scatter and time series). Zoom is off by default.
  • Eight colors per theme. With more than eight datasets the colors repeat. Set your own palette for more (see Theming).
  • Large charts of separate shapes are slower. Sunburst, waterfall, dumbbell and funnel charts draw every item as its own shape: about 320 ms for a sunburst with 10,000 items, and about 100 ms for waterfall and dumbbell charts. With up to 1,000 items, a frame takes under 30 ms. Decimation applies to lines only.
  • Label fitting is estimated. Sunburst and treemap labels are kept or hidden from an estimate of the text width, so very wide or narrow fonts can be clipped or hidden too early.
  • No image or PDF export. To save a chart as PNG, render the window with Slint's software renderer, as the gallery's --snapshot option does.
  • Sunburst data order. A parent item must come before its children in items.
  • Requirements. Slint 1.18 or later and Rust 1.88 or later.
